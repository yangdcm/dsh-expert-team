# 权威声明（AUTHORITY）

> **本表是"单源化"的唯一约定**：每个事实**只有一份权威**、**只有一个写者**，其他文件**只许引用**。
> 起草：**architect**（design 阶段，与 Ultra Spec 同时产出）｜校验：**spec-review 门禁**（`/team check` 会报违规）。
>
> 为什么需要它（真实数据）：某真实 run 的 14 条返工里 **9 条（64%）** 命中「同一事实多份拷贝 / 多写者 / 口径漂移」，
> 其中一条的原文是「CONTRACT 单写者收口（**并发事故收敛** + 6 处已核实缺陷）」—— **事故发生了才去收口**。
> 本表的目的是把这件事**提到事前**：先声明，再写。

## 怎么写

- **一行一个事实**。事实 = 会被多份文件提到、且**必须一致**的东西：术语与中英口径、拒绝码词表、功能开关的数量与 key、章节编号、指标口径与数值、边界清单、优先级定义……
- **第 1 列 = 原子事实名**（**单个词 / 短语**，**不得**用 `、` / `，` 作**并列枚举** —— 把多个事实塞进一格），**且必须能在权威文件里以定义式逐字出现**。为什么：扫描器（`scan-single-source.mjs`）只认「事实名在权威文件里的**定义式**逐字命中」；写成「功能目标、验收标准、业务规则、边界与禁止项（含禁改清单）」这类**类别标签**，它在 `SPEC.md` 里是**分节标题**（`## 功能目标` / `## 验收标准`）⇒ 完整串**必然 0 命中** ⇒ 扫描器报「事实名与定义语法不咬合」（fail-closed），而真分叉反而被漏掉。
  - 具体四条（可机判）：① 原子名，不用 `、`/`，` 并列；② 该名字必须在其权威文件里以五种定义式之一**逐字**出现（标题 / `**名**：` / 两列表格 `| 名 | 定义 |` / `「名」：` / `- 名：`）；③ **不得**写权威文件里搜不到的串；④ 第 1 列**不要**用反引号包（含反引号的形态会被判成**引用语境**）—— 需要引用代码标识符时，把它写进**第 4 列**。
  - 正确例：`变现体系` / `拒绝码词表` / `轮次上限`；错误例：`功能目标、验收标准、业务规则`（并列枚举）、`§7.35 的收尾预算口径与阈值`（权威文件里搜不到的串）。
- **唯一写者**：那个人负责改它；**其他人改 = 违规**（这条直接消灭"并发写同一份文件"的事故）。
- **允许形态**：写清"其他文件能做什么"。默认写成「只许引用（指针），不得另写定义」。
- **权威文件**必须是**本 run 目录里真实存在的文件**（`SPEC.md` / `CONTRACT.md` / `PRD.md` / `RULES-CORE.md` …）。
- 定不下来的事实**不要写进来**（写了就要守）；但**没写进来而反复分叉的事实**，评审有责任要求补一行。

## 校验规则（`/team check` 会逐条查）

1. **格式**：每行必须 4 列且都非空（空行/表头/分隔行不算）。
2. **文件真实**：`唯一权威文件` 必须在本 run 目录里存在。
3. **写者合法且唯一**：写者必须是编制里的角色；**同一个权威文件不得有两个写者**（那正是并发事故的形状）。
4. **无自相矛盾**：同一个「事实类别」不得指向两个不同的权威文件。
5. **纳入治理**：本 run 里存在的核心工件（SPEC / CONTRACT / PRD / RULES-CORE）**至少要出现在某一行**里 ——
   否则它没被纳入单源化治理，迟早分叉。
